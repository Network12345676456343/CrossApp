## Лабораторна робота 2: Бібліотека Core та публікація

### Структура проєкту та архітектура
Рішення розділене на два окремі проєкти:
* `Core` (`classlib`) — спільна бібліотека, яка інкапсулює бізнес-логіку та збір системних даних.
* `Cli` (`exe`) — консольний інтерфейс, призначений виключно для взаємодії з користувачем і виводу.

Напрямок залежностей: `Cli` -> `Core` (односторонній).

Планована структура в Core:
* `Core/Dto/` — record-типи передачі даних.
* `Core/Domain/` — сутності з поведінкою та інваріантами.
* `Core/Storage/` — реалізації сховищ.

### Порівняння режимів публікації та середовищ виконання (Runtime)

| RID | Режим публікації | Розмір publish | Потрібен встановлений .NET Runtime | Опис середовища |
| :--- | :--- | :--- | :--- | :--- |
| `win-x64` | **self-contained** | ~76.7 МБ | **Ні** | Містить у собі повну копію CoreCLR та системні збірки BCL. Автономний запуск на Windows. |
| `win-x64` | **framework-dependent** | ~0.3 МБ | **Так (.NET 10)** | Містить лише скомпільований код застосунку. Залежить від встановленого в системі .NET 10 Runtime. |
| `linux-x64` | **self-contained** | ~78.8 МБ | **Ні** | Нативний виконуваний бінарник під Linux з власним рантаймом. Запускається без інсталяції .NET. |
| `linux-x64` | **framework-dependent** | ~0.3 МБ | **Так (.NET 10)** | Лише IL-байткод програми. Для роботи вимагає попередньо встановленого середовища .NET 10 на хості Linux. |

* **Self-contained**: пакує застосунок разом із середовищем виконання .NET Runtime (CLR) та бібліотеками BCL під конкретний RID. На цільовій системі (або в контейнері) встановлений .NET не потрібен, але розмір пакету сягає ~77–79 МБ.
* **Framework-dependent**: містить лише скомпільований код застосунку та сторонні бібліотеки. Займає мінімум місця (~0.3 МБ), проте вимагає наявності встановленого .NET 10 Runtime у хостовій системі чи контейнері.
